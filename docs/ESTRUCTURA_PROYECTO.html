Equilibrio · Documentación técnica

Estructura del proyecto

Qué hace cada carpeta y cada archivo del repositorio, y dónde está cada punto de entrada. Versión inicial: registrar ingresos y gastos, verlos en una lista, ver el saldo. Sin login, sin red, Room local.

Puntos de entrada

Si vas a abrir el proyecto por primera vez, empieza aquí:

app/src/main/java/mx/equilibrio/app/MainActivity.kt

La única Activity de la app. Arranca Compose y monta EquilibrioNavHost. Esto es lo que se ejecuta al abrir la app en el teléfono/emulador.

app/src/main/java/mx/equilibrio/app/EquilibrioApp.kt

La clase Application, anotada @HiltAndroidApp. Es lo primero que se inicializa (antes que cualquier Activity) — aquí arranca el grafo de inyección de dependencias de Hilt.

app/src/main/java/mx/equilibrio/app/navigation/EquilibrioNavHost.kt

El mapa de pantallas. Rutas actuales: home (Inicio), quick_entry (Registro rápido / edición), accounts (Cuentas) y add_account (alta de cuenta). Si agregas una pantalla nueva, se registra aquí.

Arquitectura en tres capas

Cada módulo de Gradle es una carpeta en la raíz del proyecto. La regla dura: core-domain no depende de nada de Android; feature-* nunca importa core-data directamente — solo habla con core-domain.

Presentación (pantallas) ──▶ Dominio (reglas de negocio) ──▶ Datos (Room) :feature-home :feature-entry :feature-accounts :feature-categories :feature-goals :feature-reports ← pantallas Compose │ │ │ └───────┬────────┴────────┬───────┘ ▼ :core-domain ← Kotlin puro, sin Android ▲ │ :core-data ← Room, implementa las interfaces de core-domain :core-ui ← design system, no depende de nada del proyecto :app ← Application, MainActivity, navegación, conecta todo con Hilt

Módulos, carpeta por carpeta

core-domain/ Kotlin puro

Modelos y reglas de negocio. Cero dependencias de Android, Room o red — por eso sus tests corren en milisegundos sin emulador.

ArchivoQué hace
model/TransactionKind.ktEnum INCOME / EXPENSE.
model/Classification.ktEnum FIXED/VARIABLE/ESSENTIAL/RECREATIONAL + isValidFor(kind), la regla que dice qué clasificación es válida para cada tipo.
model/AccountType.ktEnum CASH/BANK/CREDIT_CARD — las tres se usan ya (alta de cuentas tiene una variante de formulario por tipo).
model/Account.ktModelo de una cuenta: id, userId, name, type, balanceCents, creditLimitCents, statementDay, dueDay, colorSlot, lastDigits: Int? (últimos 4 dígitos de la tarjeta/cuenta, nullable — null se muestra como "****" en la UI).
model/CategoryType.ktEnum INCOME/EXPENSE para categorías.
model/Category.ktModelo de una categoría: id, userId, name, type, colorSlot, icon, isSystem, sortOrder.
model/Transaction.ktModelo de un movimiento. Su constructor rechaza un par (kind, classification) inválido o un monto ≤ 0 — un movimiento incorrecto no puede existir en memoria. Incluye categoryId: String? (FK a Category, nullable).
repository/TransactionRepository.ktInterfaz: qué puede hacerse con movimientos (observar, guardar, borrar). core-data la implementa.
repository/AccountRepository.ktInterfaz: observar/guardar/borrar cuentas.
repository/CategoryRepository.ktInterfaz: observar/guardar/borrar categorías. Mismo patrón que AccountRepository.
usecase/*.ktUn caso de uso por acción: ObserveTransactions, ObserveBalance, ObserveAccounts, SaveTransaction, DeleteTransaction, GetTransaction, GetAccount, SaveAccount, DeleteAccount, GetCategories, SaveCategory, DeleteCategory. Cada uno es una clase con un solo método invoke().
src/test/.../ClassificationTest.kt8 tests: los pares válidos e inválidos de clasificación.
src/test/.../TransactionTest.kt5 tests: constructor de Transaction con datos válidos e inválidos.

core-data/ Android · Room

Persistencia. Implementa las interfaces que pide core-domain.

ArchivoQué hace
local/entity/UserEntity.ktTabla users — el usuario local único (sin login).
local/entity/AccountEntity.ktTabla accounts — incluye columnas de RF04 (tarjetas). last_digits: Int? (últimos 4 dígitos, nullable) agregado en la migración 1→2.
local/entity/TransactionEntity.ktTabla transactions. classification es nullable a propósito: un movimiento sin clasificar existe, solo no se cuenta para nada que dependa de eso. category_id: String? (renombrado desde category_key en la migración 2→3) es FK real a categories.id.
local/entity/CategoryEntity.ktTabla categories (migración 2→3): id, user_id (FK), name, type, color_slot, icon, is_system, sort_order + bloque de sync. Mismo patrón que AccountEntity.
local/dao/TransactionDao.ktobserveAll, observeBalanceCents (suma ingresos − gastos en SQL, no en Kotlin), upsert, markDeleted (borrado lógico).
local/dao/AccountDao.ktObservar/guardar/borrar cuentas, contar cuántas hay.
local/dao/CategoryDao.ktObservar/guardar/borrar categorías por user_id, borrado lógico. Mismo patrón que AccountDao.
local/dao/UserDao.ktLeer/crear el usuario local.
local/EquilibrioDatabase.ktLa base Room: declara las entidades (incluye CategoryEntity), versión 3, exportSchema = true.
local/Migrations.ktMIGRATION_1_2: agrega accounts.last_digits. MIGRATION_2_3: crea categories y recrea transactions completa para agregar la FK real category_id (SQLite no soporta agregar FK con ALTER directo). Ambas no destructivas.
mapper/TransactionMapper.ktConvierte entidad Room ↔ modelo de dominio (incluye fecha ↔ epoch millis, categoryId).
mapper/AccountMapper.ktIgual, para cuentas (incluye lastDigits).
mapper/CategoryMapper.ktIgual, para categorías.
prefs/LocalSession.ktEn el primer arranque: genera un userId (UUID), lo guarda en DataStore, crea la cuenta "Efectivo". Después de eso, siempre devuelve el mismo id.
repository/TransactionRepositoryImpl.ktImplementación real de TransactionRepository usando el DAO.
repository/AccountRepositoryImpl.ktIgual, para cuentas.
repository/CategoryRepositoryImpl.ktIgual, para categorías.
di/DataModule.ktMódulos de Hilt: cómo se construye la base de datos (con las migraciones registradas) y qué implementación usar para cada interfaz, incluyendo CategoryDao/CategoryRepository.
schemas/…/{1,2,3}.jsonEsquemas exportados de Room por versión — no se editan a mano, se regeneran solos. Versión 1 = esquema inicial, 2 = + last_digits, 3 = + categories y category_id.
src/androidTest/.../TransactionDaoTest.kt4 tests instrumentados (corren en emulador/dispositivo): upsert, saldo agregado, borrado lógico.

core-ui/ Android · Compose

El sistema de diseño. Traduce el manual de identidad a código — nadie fuera de aquí usa un Color crudo.

ArchivoQué hace
theme/Color.ktToda la paleta, claro y oscuro (verde, morado, neutros, colores de estado).
theme/Tone.ktDomainTone (verde/morado, clasifica dinero) y FeedbackTone (éxito/error/advertencia/info, describe confianza del sistema). Son dos tipos distintos a propósito: ningún componente acepta ambos.
theme/Type.ktTipografía: Plus Jakarta Sans (variable) para cifras/títulos, Inter (variable) para cuerpo. Los montos siempre usan cifras tabulares.
theme/Spacing.ktEscala de espaciado de 4pt y tamaños táctiles mínimos.
theme/Shape.ktRadios de esquina (chip, tarjeta, pill).
theme/Motion.ktCurvas de animación — ninguna con rebote, a propósito.
theme/Elevation.ktSombras con tinta a baja opacidad, nunca negro puro.
theme/Theme.ktEquilibrioTheme: junta todo lo anterior y también puentea a MaterialTheme, para que componentes crudos de Material 3 (como el selector de fecha) hereden la marca en vez del morado por defecto de Material.
res/font/*.ttfLas dos fuentes variables, empaquetadas localmente (licencia SIL OFL incluida en core-ui/licenses/).
components/Eq*.ktLos componentes: EqAmount (montos), EqBadge (insignias de clasificación), EqCard, EqButton, EqTextField, EqSegmentedControl, EqDomainToggleOption (el toggle Esencial/Recreativo), EqInlineValidation, EqSnackbar, EqDialog, EqEmptyState, EqTopBar, EqFab, EqBottomNav (barra de navegación capsular flotante inferior, destinos EqNavDestination: HOME/ACCOUNTS/CATEGORIES/GOALS/REPORTS). Cada archivo trae su @Preview.

feature-entry/ Pantalla

Registro rápido — sirve para dar de alta y para editar (recibe un transactionId opcional por navegación).

ArchivoQué hace
QuickEntryUiState.ktEl estado de la pantalla: monto, tipo, clasificación, fecha, nota, si está guardando.
QuickEntryEvent.ktLos eventos que la UI puede disparar (cambiar monto, cambiar clasificación, guardar…).
QuickEntryViewModel.ktLa lógica: si cambias de Gasto a Ingreso, resetea la clasificación; valida fecha futura; guarda usando los casos de uso de core-domain.
QuickEntryScreen.ktLa UI en Compose: toggle Gasto/Ingreso, campo de monto, toggle de clasificación, selector de fecha, nota, botón guardar.

feature-home/ Pantalla

Inicio — saldo y lista de movimientos.

ArchivoQué hace
HomeUiState.ktEstado de la pantalla + TransactionUi, que traduce un movimiento a lo que se muestra (color, etiqueta, signo).
HomeEvent.ktEventos: pedir borrar, confirmar borrado, cancelar borrado.
HomeViewModel.ktCombina el saldo y la lista de movimientos en un solo StateFlow reactivo — se actualiza solo, sin recargar nada a mano.
HomeScreen.ktLa UI: tarjeta de saldo, lista de movimientos, estado vacío, estado de carga, diálogo de confirmación al borrar.

feature-accounts/ Pantalla

Cuentas — carrusel de tarjetas (una por cuenta) y alta de cuenta nueva.

ArchivoQué hace
AccountsUiState.ktEstado de la pantalla + AccountUi, que traduce una cuenta a lo que se muestra: incluye colorSlot, lastDigits: Int? y maskedDigits ("•••• 4821" o "****" si lastDigits es null). También trae selectedAccountId para saber qué cuenta está activa en el carrusel.
AccountsViewModel.ktCombina las cuentas observadas con la selección activa; expone onAccountSelected(id) como hook para conectar después la sección de detalle (todavía no implementada).
AccountsScreen.ktLa UI: topbar "Cuentas" + AccountsCarousel + FAB que navega a AddAccountScreen.
AccountsCarousel.ktHorizontalPager con peek (se asoma la siguiente tarjeta), snap, y escala/alpha por página para dar profundidad al cambiar de cuenta — animación continua, sin curvas con rebote (respeta Motion.kt).
AccountCard.ktLa tarjeta individual: gradiente por tipo/colorSlot (accountGradient(), internal para reusarse en el color picker del formulario), nombre, dígitos enmascarados, disponible, vencimiento si aplica. Sin ícono NFC (no se maneja todavía).
AddAccountEvent.ktEventos del formulario de alta: cambios de campo + SaveClicked.
AddAccountUiState.ktEstado del formulario: inputs como String, validación centralizada en validate() (se ejecuta al guardar, no en cada tecla).
AddAccountViewModel.ktArma el Account completo al guardar: creditLimitCents/statementDay/dueDay solo si el tipo es CREDIT_CARD; lastDigits null si es CASH. El id de cuenta nuevo se genera con UUID.randomUUID(), igual que el resto de las PK del esquema.
AddAccountScreen.ktFormulario con 3 variantes según AccountType (un solo composable data-driven, no 3 pantallas separadas): EqSegmentedControl para elegir tipo, campos de crédito solo si aplica, últimos 4 dígitos si no es efectivo, y el selector de colorSlot con los 3 gradientes reales de AccountCard.kt.

feature-categories/ Pantalla

Categorías — listado y alta de categoría nueva (tipo INCOME/EXPENSE).

ArchivoQué hace
CategoriesUiState.ktEstado de la pantalla + CategoryUi, que traduce una categoría a lo que se muestra (typeLabel "Ingreso"/"Gasto").
CategoriesViewModel.ktObserva GetCategories (Flow, pese al nombre), ordena por sortOrder.
CategoriesScreen.ktLa UI: topbar "Categorías" + lista + FAB que navega a AddCategoryScreen.
CategoryRow.ktLa fila de cada categoría: avatar circular con la inicial del nombre (color sólido, sin gradiente) + nombre + tipo. categoryPalette() calca accountPalette() de feature-accounts: INCOME=verde, EXPENSE=morado, colorSlot%3 elige el tono. El campo icon: String de Category todavía no se usa — no hay catálogo de íconos en el repo.
AddCategoryEvent.ktEventos del formulario de alta: cambios de campo + SaveClicked.
AddCategoryUiState.ktEstado del formulario de alta.
AddCategoryViewModel.ktArma la Category completa al guardar: id con UUID.randomUUID(), sortOrder = tamaño actual de la lista (se agrega al final), userId sacado de observeAccounts().first() (el módulo no depende de core-data, no puede inyectar la sesión local directo — mismo truco que AddAccountViewModel).
AddCategoryScreen.ktFormulario de alta: nombre, tipo (EqSegmentedControl INCOME/EXPENSE), selector de colorSlot.
